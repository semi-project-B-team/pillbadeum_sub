# 복약지도 테스트 계정 준비

일정 담당자가 프로필·약 등록 파트를 따로 구현하거나 SQL을 하나씩 실행할 필요 없도록, 기존 회원 계정에 테스트 데이터 전체를 준비한다.
회원가입·로그인 API와 비밀번호는 그대로 사용한다. 이 도구는 회원 비밀번호와 기존 약 마스터를 변경하지 않는다.

## 한 번에 준비

Java 21, PowerShell 5.1 이상과 Gradle 캐시의 MySQL JDBC 드라이버를 사용한다. 서버 폴더에서 실행한다.

```powershell
.\scripts\prepare-medication-fixture.ps1 -Email '가입한 이메일'
```

이 명령은 프로필·약·기본 알림 설정을 **실제 DB에 저장**한다. 환경변수 DB 설정을 우선하고 없으면 프로젝트 `.env`를 읽는다.
터미널 환경변수와 프로젝트 `.env`의 DB 접속 정보가 다르면 `-LocalFileDb`를 붙여 자식 검사 프로세스만 `.env` 값을 사용하게 할 수 있다.
사용자·IDE 환경변수와 `.env` 파일을 덮어쓰지는 않는다.

조회만 할 때:

```powershell
.\scripts\prepare-medication-fixture.ps1 -Email '가입한 이메일' -InspectOnly
```

이 계정의 테스트 일정을 다시 초기 상태로 맞출 때:

```powershell
.\scripts\prepare-medication-fixture.ps1 -Email '가입한 이메일' -Reset
```

다음 세 이름은 이 도구의 테스트 프로필로 예약한다: `테스트본인`, `테스트엄마`, `테스트아빠`.
이미 같은 이름이 있으면 같은 회원의 가장 작은 프로필 ID를 사용한다.
기본 재실행은 없는 데이터만 추가하고 기존 일정은 보존한다. `-Reset`은 이 세 테스트 프로필에 연결한 타이레놀·다른 약의 첫 내 약 행만 초기화한다.
다른 회원과 이 세 이름 외의 프로필은 변경하지 않는다. 같은 회원에 대한 준비 명령은 회원 행 잠금으로 직렬화한다.
중간 실패는 생성·일정 초기화 작업 전체를 롤백한다.

## 준비되는 데이터

기존 약 마스터의 타이레놀 한 종과 타이레놀이 아닌 다른 약 한 종을 참조한다.
현재 샘플 마스터에서는 타이레놀정500밀리그램과 아모디핀정5밀리그램이다. 새로운 약 품목이나 가짜 함량은 만들지 않는다.

| 프로필 | 약 | 초기 일정 | 용도 |
| --- | --- | --- | --- |
| 테스트본인 / SELF | 타이레놀 | 없음 | 일정 추가·수정·삭제·재등록 |
| 테스트본인 / SELF | 다른 약 | 어제부터 오늘+7일까지 | 그만 먹기·캘린더·복용 예정 조회 |
| 테스트엄마 / MOTHER | 타이레놀 | 어제부터 오늘+7일까지 | “엄마 타이레놀” 대상 추론 |
| 테스트엄마 / MOTHER | 다른 약 | 오늘-7일부터 어제까지 | 이미 종료된 일정 중단 409 |
| 테스트아빠 / FATHER | 타이레놀 | 어제부터 오늘+7일까지 | 같은 약의 프로필 후보 질문 |
| 테스트아빠 / FATHER | 다른 약 | 내일부터 오늘+7일까지 | 시작 전 일정 중단 409 |

일정 있는 약은 07:00·11:00·17:00, 1회 1개, 식후 30분이다. 이는 테스트용 입력값이며 복용법 추천이 아니다.
날짜는 실행 당일 한국 시간으로 계산한다. 날짜가 지나 초기 상태가 달라졌으면 `-Reset`으로 다시 준비한다.
알림 설정이 없으면 꺼진 상태를 만들고, 이미 설정되어 있으면 보존한다. 동의를 대신 기록하거나 브라우저 구독·푸시 발송·Live 세션을 생성하지 않는다.

## 바로 테스트

실행 결과에 회원 ID, 세 프로필 ID, 여섯 내 약 ID, 실제 기간·시각이 나온다.
같은 내용은 Git에서 제외되는 `build/medication-fixture.txt`에도 저장한다. 이메일·비밀번호·JWT·DB 접속 정보는 보고서에 쓰지 않는다.

1. Swagger의 `POST /api/auth/login`으로 이 계정에 로그인하고 accessToken을 Authorize에 넣는다.
2. 출력된 테스트본인 프로필 ID와 타이레놀 내 약 ID로 `PUT /api/profiles/{profileId}/drugs/{myDrugId}/schedule`을 호출한다.
3. 캘린더·복용 예정 목록에서 본인·엄마·아빠 일정이 함께 조회되는지 확인한다.
4. 본인의 진행 중 약은 중단 200, 엄마의 이미 종료된 약과 아빠의 시작 전 약은 중단 409를 확인한다.
5. Live 페이지에도 같은 본인 ID·타이레놀 ID와 오늘 날짜를 넣는다. “오늘부터 이틀 타이레놀”, “엄마 타이레놀 일정 삭제해줘”, “아빠 타이레놀 그만 먹을래”를 확인한다.
6. 엄마·아빠 타이레놀 일정이 둘 다 있는 초기 상태에서 “타이레놀 일정 삭제해줘”를 말하고 프로필 후보를 묻는지 확인한다.
7. 테스트가 끝나거나 다시 시작할 때 `-Reset` 한 번으로 이 테스트 데이터의 일정 상태를 복원한다.

다른 회원의 일정 조회 권한 검증용 ID 한 쌍도 출력한다. 그 계정으로 로그인할 필요 없이 현재 테스트 계정의 토큰으로 조회했을 때 404여야 한다.
푸시 실수신은 별도의 본인 브라우저 서비스 워커·구독이 필요하다. 실제 음성·푸시까지 준비됐다고 보지는 않는다.

전체 API 시나리오는 [검증 기록](MEDICATION_VERIFICATION.md), 프론트 계약은 [연결 문서](MEDICATION_FRONTEND_HANDOFF.md)를 따른다.
