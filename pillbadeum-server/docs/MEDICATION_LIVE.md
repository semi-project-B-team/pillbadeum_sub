# GPT-Live 복약 일정 관리

기존 단발 음성 API와 별도로 GPT-Live 음성 대화를 연결합니다. 브라우저는 WebRTC로 음성을 주고받고,
서버는 sideband WebSocket으로 사용자·답변 자막과 client delegation 이벤트를 받아 기존 일정 관리 서비스를 호출합니다.
새 테이블이나 라이브러리는 추가하지 않습니다. 원본 음성과 대화·초안은 DB·파일·로그에 저장하지 않습니다.
직접 입력 약의 DB 변경과 테스트 순서는 [직접 입력 약 일정](MEDICATION_CUSTOM_NAME.md)을 참고합니다.

## 실행

1. 통합 변경 sql/03_MEDICATION_UPDATE.sql이 적용된 로컬 DB와 로그인 JWT를 준비합니다. 새 DB는 01 → 02(샘플 선택) → 03 순서입니다.
2. 개인 `.env`에 `OPENAI_API_KEY`, `OPENAI_CHAT_MODEL`을 지정합니다. 후자는 구조화 출력 지원 모델이어야 합니다.
3. Live 모델은 `OPENAI_LIVE_MODEL`, 기본 `gpt-live-1`입니다. 음색은 `OPENAI_LIVE_VOICE`, 기본 `marin`입니다.
4. 서버를 local 프로필로 재시작하고 `http://localhost:8080/dev/medication-live`를 엽니다.
5. 회원 JWT, 해당 회원의 프로필 ID, 캘린더에서 선택한 날짜를 넣고 음성 대화를 시작합니다. 내 약 ID는 선택입니다.

OpenAI 모델에 대한 실제 프로젝트 사용 권한과 연결 성공은 호출 시 확인됩니다. 키·해석 모델이 없으면 세션 생성 전에 거절해야 합니다.
이 화면은 OpenAI API 키를 받지 않습니다. 회원 JWT는 브라우저 메모리에서만 사용하며 저장소에 보관하지 않습니다.
음성 대화는 실제 세션 사용 요금과 backend Responses 호출 요금이 발생합니다.
마이크는 localhost 또는 HTTPS에서 권한을 받아야 하며, 자동 음성 재생이 막히면 화면의 오디오 재생 버튼을 누릅니다.

## 동작 규칙

- 첫 인사는 “안녕하세요 AI 복약도우미입니다. 어떻게 일정 등록을 도와드릴까요?”로 한 번만 하도록 시작 입력에 넣습니다. 사용자가 약·기간을 말하면 등록 의사를 다시 묻지 않습니다. Live 생성 음성이므로 실제 인사·표현은 실연동으로 확인합니다.
- 시작 인사부터 평소의 약 1.5배 속도로 말하도록 Live에 지시합니다. 날짜·시간·개수는 또렷하게 발음하고, 사용자가 속도 변경을 요청하면 따릅니다. 이는 말하기 스타일 지시이며 정확한 재생 배속을 보장하지 않습니다. 서버 재시작 후 새 대화부터 적용됩니다.
- 기본 설정 안내는 “기본 하루 3번, 7·11·17시, 1회 1개, 식후 30분. 적용할까요?”처럼 압축합니다. 이 부분은 4초 이내를 목표로 더 빠르게 말하도록 지시하고 오전·오후와 항목 이름의 반복을 줄입니다. 실제 개수·복용 때는 사용자 값 또는 현재 약 설정을 사용하며 예시 값으로 덮지 않습니다. 분 단위 시각도 보존합니다. Live에는 발화 길이의 하드 제한이 없어 정확한 4초를 보장하거나 4초에 음성을 잘라내지는 않습니다.
- 사용자가 말한 뒤 약 1초 동안 말을 멈추면 현재 발화를 처리하도록 지시합니다. 미완성 문장도 현재 내용으로 해석하고 나머지는 기본 설정으로 제안하며, 발화 전 무음·주변 소리는 요청으로 만들지 않습니다. 다시 말하면 정정을 반영합니다. GPT-Live의 공개 세션 설정에는 `silence_duration_ms`가 없으므로 프롬프트 기반 목표이며 정확한 1000ms 종료나 응답 시작을 보장하지 않습니다. Realtime API의 VAD 설정과는 다릅니다.
- 시작일을 말하지 않으면 이미 화면에서 선택한 날짜를 사용합니다. 약을 말하지 않으면 선택한 내 약을 사용하며 항상 회원 소유인지 검사합니다.
- 내 약 ID를 생략해도 프로필만 있으면 시작할 수 있습니다. “오늘부터 일주일 혈압약”처럼 말하면 기존 약과 유일하게 일치하는 경우 그 약을 사용하고, 일치하지 않으면 `item_seq=NULL`, `custom_name=혈압약`, `source=MANUAL`인 내 약 행과 일정을 함께 만듭니다. 이름은 실제 사용자 발화에서만 가져오며 약 이름도 선택 약도 없으면 이름을 질문합니다.
- 직접 입력 약도 제안·취소 단계에서는 DB에 생성하지 않습니다. 동의 또는 명시적 기본값 위임 후에만 저장하며 완료 응답에는 새로 발급된 실제 `myDrugId`가 포함됩니다. 이후 기존 일정 조회·수정·삭제·그만 먹기 API를 그대로 사용합니다. 일정 삭제는 직접 입력 이름과 내 약 행도 남깁니다.
- “오늘부터 이틀 타이레놀”처럼 약과 기간만 말해도 등록 요청입니다. 빠진 기간·시각·1회 개수를 기본 설정으로 채운 완성 초안을 만들고 한 번에 제안합니다. 제안 중에는 저장하지 않습니다.
- “응”, “네”, “그렇게 해줘” 등 짧은 동의는 해당 세션에 실제 보관한 최신 초안에만 적용합니다. 동의 시 모델을 다시 호출하지 않고 그 초안을 검증·저장합니다. assistant 자막이나 모델 플래그만으로 동의를 만들 수 없습니다.
- “저녁에만” 같은 수정은 기존 사용자 항목을 보존하면서 초안을 바꿔 다시 제안합니다. “아니요”로 거절하면 바꿀 내용만 요청하고 같은 기본값 질문을 반복하지 않습니다.
- “하루 세 번”은 07:00·11:00·17:00을 제안합니다. “아침·점심·저녁”은 각각 해당 기본 슬롯을 제안하며 “저녁에만”은 17:00 하나입니다. 구체 시각을 말하면 그 값을 우선합니다. 1~3개 시각과 1회 1~10개 범위는 유지합니다.
- “알아서 저장해”, “기본값으로 해줘”처럼 맡긴 경우에는 추가 확인 없이 빠진 항목에 기본값을 적용합니다.
  AI의 useDefaults 플래그뿐 아니라 실제 사용자 자막의 근거도 검사합니다. assistant가 제안한 말을 사용자 허락으로 취급하지 않습니다.
- “몰라”만 말하면 기본 설정으로 채운 초안을 제안합니다. 명시적 위임이나 초안 동의 없이 저장하지 않습니다.
- 기본값은 선택 날짜 하루, 07:00·11:00·17:00, 현재 약의 1회 개수·복용 때입니다. 새 직접 입력 약은 1회 1개·식후 30분을 화면 입력 기본값으로 제안합니다. 횟수 N을 이미 말했다면 기본 시각의 앞 N개만 사용합니다.
- 이미 정한 날짜·기간·시각·개수는 보존합니다. 잘못된 시각·역전된 기간·범위 밖 개수는 기본값으로 덮지 않고 다시 묻습니다.
- 음성은 등록·전체 교체, 일정 삭제, 그만 먹기를 지원합니다. 같은 약의 기존 일정 등록은 PUT처럼 교체됩니다. 약 자체·프로필 삭제와 일괄 처리는 지원하지 않습니다.
- “엄마 타일레놀 먹던 거 일정 삭제해줘”는 회원 소유의 일정이 있는 약에서 프로필·약 이름을 좁힙니다. 엄마·어머니 같은 관계 표현, 약 이름의 한 글자 차이(네 글자 이상), 함량을 함께 비교합니다. 모델이 고른 ID만 믿거나 명시한 프로필을 화면 선택값으로 바꾸지 않습니다.
- 대상이 하나면 명시한 요청을 바로 실행합니다. 여러 프로필·함량이 남으면 어느 대상인지 한 번만 물어보고 “500짜리” 같은 후속 정보로 좁힙니다. 없는 일정, 부정·취소, 사용자 원문에 없는 이름·실행 근거로는 실행하지 않습니다. 새로 말한 대상 이름이 없는 경우 화면 선택 일정은 사용자가 “선택한 일정”이라고 지칭했을 때 사용합니다.
- 일정 삭제는 해당 내 약 행의 시작일·종료일·복용 시각을 모두 비웁니다. 과거를 포함한 그 일정의 캘린더 표시가 사라지며 약·프로필은 남습니다.
- “그만 먹을래”, “오늘까지만”은 기존 그만 먹기 서비스를 호출해 종료일만 한국 시간 오늘로 줄입니다. 시작일·복용 시각·1회 개수·복용 때와 과거 캘린더 표시는 보존하며 오늘 남은 시각까지 포함하고 내일부터 제외합니다. 시작 전 일정이나 이미 끝난 일정은 기존 409 규칙을 따릅니다. 실제 복약 완료 체크 기록을 새로 만드는 기능은 아닙니다.
- 실행 준비 중 새 발화가 들어와 해석 시점의 사용자 자막 버전이 달라졌으면 이전 결정은 폐기합니다.
  다음 delegation에서 정정된 전체 대화를 다시 해석합니다. 이미 커밋된 등록·삭제·중단을 음성 중단만으로 되돌리지는 않습니다.
- 동일 delegation ID와 같은 사용자 자막 버전에 대한 중복 요청은 재실행하지 않습니다. 실패 결과도 자동 재시도하지 않습니다.
- 등록·삭제·그만 먹기 트랜잭션이 성공한 뒤에만 Live에 완료 문구를 전달합니다. Live 경로는 별도 TTS API를 호출하지 않습니다.
- 등록은 “등록했어요.”, 삭제는 “일정을 삭제했어요.”, 그만 먹기는 “오늘까지만 복용하도록 변경했어요.”라고 말하고 자동 종료합니다. 서버는 추가 업무 요청을 차단하고 입력 음소거를 요청합니다. 브라우저는 업무 성공 확인과 완료 자막, 실제 출력 오디오 활동 뒤의 700ms 무음을 함께 보고 종료합니다. 이는 완료 추정이며 자막 수신 간격만으로 재생 완료를 단정하지 않습니다. 재생 정지·분석 미지원·네트워크 문제 등에 대비해 서버는 업무 성공 후 8초에 연결을 정리합니다(기존 60초 상한이 먼저 오면 우선). 실패에는 자동 완료 처리를 하지 않습니다.

## API

모든 업무 API는 기존 회원 Bearer JWT가 필요합니다.

| 요청 | 동작 |
| --- | --- |
| `POST /api/medication/live/sessions` | 선택값·SDP offer로 시작. 201과 로컬 sessionId·SDP answer·expiresAt |
| `GET /api/medication/live/sessions/{sessionId}` | 본인 대화의 상태·질문·부족 항목·적용 기본값·마지막 업무 결과 |
| `DELETE /api/medication/live/sessions/{sessionId}` | 추가 변경 차단 후 원격 연결 종료. 204. 이미 완료한 업무는 되돌리지 않음 |

POST 본문은 `{ "sdp": "<browser offer>", "selectedProfileId": 13, "selectedMyDrugId": 25, "selectedDate": "2026-11-03" }`입니다.
`selectedMyDrugId`는 생략하거나 `null`로 보낼 수 있습니다. 값을 넣으면 양수이며 선택한 프로필 소유여야 합니다. `selectedProfileId`와 `selectedDate`는 필수입니다.
실제 SDP는 브라우저가 생성해야 하므로 Swagger에서 문자열을 임의로 넣어 음성 연결을 검사할 수는 없습니다.
다른 회원·없는 세션은 동일하게 404이고, 같은 회원의 중복 대화 시작은 409입니다.

로컬 화면과 JS만 GET 공개이며, 컨트롤러 자체도 local 프로필에만 존재합니다. 업무 API를 permitAll로 풀지 않습니다.
client data channel은 자막·연결 상태 관찰과 session.close만 허용합니다. 서버 업무 판단은 backend가 맡습니다.

대화 예시(등록된 약 이름과 1회 개수에 따라 달라집니다):

> AI: 안녕하세요 AI 복약도우미입니다. 어떻게 일정 등록을 도와드릴까요?
>
> 사용자: 오늘부터 이틀 타이레놀.
>
> AI: 네, 오늘부터 2일 동안 타이레놀 등록 도와드릴게요. 기본 하루 3번, 7·11·17시, 1회 1개. 적용할까요?
>
> 사용자: 응.
>
> AI: 등록했어요. (대화 자동 종료)

제안 대기 상태는 `AWAITING_CONFIRMATION`입니다. 제안은 서버 메모리에만 보관하고 수정·취소·종료·실패 시 교체 또는 폐기합니다.

업무 완료 상태는 `SAVED`, `DELETED`, `STOPPED`입니다. `completedOperation`은 `{ "action": "DELETE", "profileId": 14, "myDrugId": 27 }`처럼 실제 처리 대상을 반환합니다. 삭제는 `savedSchedule=null`이며 그만 먹기는 오늘로 줄인 일정을 `savedSchedule`에 반환합니다. 클라이언트는 `completedOperation`으로 성공 여부·종류를 구분하고 캘린더를 갱신합니다. 새 DB 표·컬럼이나 공개 업무 API는 추가하지 않습니다.

## 연결·운영 범위

- 서버 키로 `POST /v1/live/sessions`를 호출하고 `session.id`로 `/v1/live/sessions/{id}/attach`에 접속합니다.
- 입력·출력 transcript delta를 타임스탬프와 함께 수집합니다. delegation 이벤트에는 사용자 문장이 없으므로 실제 자막과 선택값으로 backend 입력을 만듭니다.
- 서버가 `session.commentary.append`로 질문·저장 결과를 돌려주며, 브라우저는 서버 상태를 조회해 캘린더를 갱신합니다.
- 회원당 대화 하나, 서버 전체 기본 10개입니다. `OPENAI_LIVE_MAX_SESSIONS`로 조정합니다.
- 대화 제한은 세션 시작 요청을 받은 시점부터 최대 60초입니다. `OPENAI_LIVE_MAX_SECONDS`로 더 짧게 설정할 수 있고, 60초를 넘는 값도 서버에서 60초로 제한합니다. 브라우저 타이머, 서버 상태 조회·저장 직전 검사, 1초 주기 정리로 종료합니다. 시간 초과 후 새 저장은 실행하지 않으며 이미 저장된 일정은 유지합니다.
- 로컬 테스트 화면은 만료 시 상태 영역에 “시간이 초과되어 종료됩니다”를 즉시 표시하고 마이크·연결을 정리합니다. 서버 종료 이벤트가 타이머보다 먼저 와도 만료 시각을 확인해 같은 문구를 표시합니다. 업무 완료 후 자동 종료와 수동 종료는 각각의 안내를 유지합니다.
- 종료 버튼은 서버의 추가 저장을 차단하고 hangup합니다. 최종 사용량 수신용 sideband는 최대 3초 더 유지하고 정리합니다. 대화·저장은 이 시간 동안 재개되지 않습니다.
- Live 음성 사용량은 토큰 수가 아닌 API의 `usage.seconds`로 기록합니다. `session.usage.updated`는 누적 스냅샷이므로 합산하지 않고 마지막 값을 보관하며, `session.closed`의 최종 사용 초를 한 번 로그에 남깁니다. 예: `[OpenAiLive] 완료 : model=gpt-live-1, session=live_..., 사용 시간=24.0초, 종료 사유=close_requested (음성 토큰 수는 API 미제공)`.
- 최종 이벤트·사용량 누락, 연결 오류 또는 정리 대기 시간 초과 시 `[OpenAiLive] 최종 사용량 미확정`과 마지막 누적 초를 기록합니다. 수신 값이 없으면 `unknown`이며 0초로 간주하지 않습니다. 로컬 타이머로 잰 대화 시간은 과금 사용량으로 대체하지 않습니다. 일정 해석 모델의 입력·출력 토큰은 기존 `[OpenAiClient]` 로그에 별도로 남습니다.
- 세션 상태는 단일 서버 메모리입니다. 서버 재시작 시 대화는 복구되지 않습니다. 여러 서버 운영에는 라우팅·공유 상태 설계가 추가로 필요합니다.
- 자막은 일부 문장일 수 있고 인식 오류가 있을 수 있습니다. 실제 사용자 발화로 질문·위임·정정·저장 결과를 확인하는 실연동 검증이 필요합니다.

## 검증

`./gradlew test bootJar`와 `node scripts/test-medication-live.cjs`로 검증합니다.
Java 테스트는 세션 생성 HTTP, WebSocket 조각 조립, 회원 소유권, 정보 부족, 기본값 위임, 정정·종료 시 실행 방지와 중복 방지, 삭제·그만 먹기 대상의 프로필·오인식·함량 구분과 부정·취소 방지를 mock·로컬 fixture로 검사합니다.
브라우저 동작 테스트는 Node 가짜 DOM·WebRTC·오디오·시계로 토큰 누락, 연결 도중 종료, 늦은 세션 정리, API 오류와 미디어 해제, 완료 음성 뒤 자동 종료, 분석 미지원·재생 정지 시 유예 종료를 검사합니다.
실제 과금 세션·마이크·프로젝트 모델 권한은 이 검증과 별개이며 자동 테스트에서 호출하지 않습니다.
